## CONTEXTO

CRM SaaS multi-tenant baseado na metodologia CASE. Foco em agências e negócios que operam com SDR + Closer. Resolve gaps do Kommo e Ramper Pipeline. Inclui IA nativa.

### 1.11 Automações (Modelo igual ao Kommo: Digital Pipeline + Salesbot)

O sistema de automação tem DUAS camadas, como no Kommo:

**CAMADA 1 — Digital Pipeline (triggers visuais por etapa)**
Na tela de configuração do pipeline, ABAIXO de cada etapa, o usuário vê os triggers
ativos daquela etapa e pode adicionar novos clicando em "+". Isso é visual:
o admin olha o pipeline e VÊ as automações que rodam em cada etapa.
Exatamente como no Kommo: Leads → Automatize → seleciona etapa → Add Trigger.

**CAMADA 2 — Salesbot / Chatbot Builder (fluxo visual no-code)**
Builder visual de arrastar e soltar para criar fluxos conversacionais e de automação.
Cada "step" pode ser: mensagem, pergunta com botões, condição, ação, timer.
O bot pode ser vinculado a uma etapa do pipeline como trigger.

```
───────────────────────────────────────────────────────────
CAMADA 1: DIGITAL PIPELINE (Triggers por etapa)
───────────────────────────────────────────────────────────

StageTrigger (trigger visual vinculado a uma etapa)
├── id (uuid, PK)
├── stage_id (FK → Stage) — a qual etapa pertence
├── pipeline_id (FK → Pipeline)
├── tenant_id (FK)
├── name (string) — ex: "Preencher data de agendamento"
├── is_active (boolean, default: true)
├── sort_order (int) — ordem de execução na etapa
├── apply_to_existing (boolean, default: false) — aplicar a leads já na etapa?
│
│  ── QUANDO EXECUTA (trigger) ──
├── trigger_event: ENUM(
│     on_enter,                  — quando lead ENTRA nesta etapa
│     on_exit,                   — quando lead SAI desta etapa
│     on_create_in_stage,        — quando lead é CRIADO diretamente nesta etapa
│     on_enter_or_create,        — combinação: entra OU cria (mais comum)
│     on_responsible_changed,    — quando muda o responsável nesta etapa
│     after_time_in_stage,       — X tempo DEPOIS de estar nesta etapa
│     on_field_changed,          — quando campo específico muda nesta etapa
│     on_message_received,       — quando lead manda mensagem estando nesta etapa
│     on_message_read,           — quando msg outbound é lida pelo lead
│     scheduled                  — executa em horário agendado (ex: todo dia 9h)
│   )
├── trigger_config (JSON):
│     Para after_time_in_stage: {delay_minutes: 1440} (24h)
│     Para on_field_changed: {field_id: "uuid", old_value: null, new_value: "any"}
│     Para scheduled: {cron: "0 9 * * 1-5", timezone: "America/Sao_Paulo"}
│     Para on_message_read: {delay_minutes: 10} (10min após leitura)
│
│  ── CONDIÇÕES (filtros — lead só passa se todas baterem) ──
├── conditions (JSON array):
│     Cada condição: {type, field, operator, value}
│     Tipos de condição:
│     - {type: "tag", operator: "has|not_has", value: "tag_name"}
│     - {type: "tag", operator: "excludes", value: "tag_name"} — excluir leads com tag
│     - {type: "field", field_id: "uuid", operator: "equals|not_equals|contains|gt|lt|is_empty|is_not_empty", value: "..."}
│     - {type: "responsible", operator: "is|is_not", value: "user_id"}
│     - {type: "origin", operator: "equals", value: "origin_id"}
│     - {type: "temperature", operator: "equals", value: "hot"}
│     - {type: "value", operator: "gt|lt|between", value: 10000}
│     - {type: "utm", field: "utm_source|utm_medium|utm_campaign", operator: "equals", value: "google"}
│     - {type: "time_in_stage", operator: "gt", value_minutes: 4320} — mais de 3 dias
│     - {type: "channel", operator: "equals", value: "whatsapp"}
│
│  ── O QUE FAZ (tipo de trigger) ──
├── action_type: ENUM(
│     salesbot,                  — executa um Salesbot/fluxo
│     create_task,               — cria tarefa
│     send_email,                — envia e-mail template
│     send_message,              — envia mensagem WhatsApp template
│     change_responsible,        — muda responsável (fixo ou round-robin)
│     change_stage,              — move para outra etapa
│     move_to_pipeline,          — move para outro funil + etapa
│     set_field,                 — preenche campo automaticamente
│     add_tag,                   — adiciona tag
│     remove_tag,                — remove tag
│     create_opportunity,        — cria nova oportunidade (duplica)
│     webhook,                   — dispara webhook externo
│     notify_user,               — notifica usuário (push/email)
│     ai_suggest_response,       — IA gera sugestão de resposta
│     schedule_meeting,          — agenda reunião com Closer
│     duplicate_to_pipeline      — duplica card para outro pipeline
│   )
├── action_config (JSON) — configuração específica por tipo:
│
│     Para salesbot:
│       {bot_id: "uuid"} — referencia o SalesBot builder
│
│     Para create_task:
│       {task_template_id: "uuid"} OU
│       {title: "Follow-up #1", type: "follow_up", assigned_role: "sdr",
│        due_offset_minutes: 1440, priority: "high", sla_minutes: 120}
│
│     Para send_email:
│       {template_id: "uuid", from_user: "responsible"} — usa template de e-mail
│
│     Para send_message:
│       {template_id: "uuid", channel: "whatsapp"} — usa template de WhatsApp
│
│     Para change_responsible:
│       {mode: "fixed", user_id: "uuid"} OU
│       {mode: "round_robin", user_ids: ["uuid1", "uuid2"]} OU
│       {mode: "by_field", field_id: "uuid"} — responsável baseado num campo
│
│     Para change_stage:
│       {stage_id: "uuid"}
│
│     Para move_to_pipeline:
│       {pipeline_id: "uuid", stage_id: "uuid"}
│
│     Para set_field:
│       {field_id: "uuid", value: "{{now}}"} — suporta variáveis dinâmicas
│       Variáveis: {{now}}, {{now+30d}}, {{contact.name}}, {{opportunity.value}},
│                  {{stage.name}}, {{responsible.name}}, etc.
│
│     Para add_tag / remove_tag:
│       {tag_id: "uuid"} OU {tag_name: "Confirmado"}
│
│     Para webhook:
│       {url: "https://...", method: "POST",
│        headers: {"Authorization": "Bearer ..."},
```
